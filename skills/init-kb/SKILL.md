# init-kb — 初始化知识库

将当前目录初始化为结构化知识库，支持个人查阅和 Agent 协作。

## 理念

参考 [karpathy 的 vibe-coding 笔记](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f) 和 [llm_wiki](https://github.com/nashsu/llm_wiki) 的理念：知识库是给 AI 读的 wiki，每个条目都应该让 Claude 在没有上下文的情况下，也能准确理解这个东西是什么、怎么用、为什么存在。

## 触发条件

- `/init-kb`
- 自然语言：「帮我初始化知识库」、「把这个目录变成知识库」、「初始化知识库」等

## 初始化后的目录结构

```text
<目标目录>/
├── CLAUDE.md                    # 目录主题声明，引用本地 skills/kb/SKILL.md
├── .claude/
│   └── settings.json            # hook 配置，指向本目录 kb-update.sh
├── skills/
│   └── kb/
│       ├── SKILL.md             # 定义 /kb 命令（本地生效，不挂载全局 ~/.claude/skills/）
│       └── kb-update.sh         # 会话首次检测 + 增量更新脚本
└── .knowledge/
    ├── index.md                 # 快速索引表（所有条目一行摘要）
    └── projects/
        └── <name>.md            # 每个条目的详细知识文件
```

**重要：** `skills/kb/` 是本目录专属 skill，不创建全局 symlink，通过 CLAUDE.md 声明路径让 Claude 自动读取。

## 执行流程

### 第一步：分析目录

列出当前目录的一级子目录和文件，推断目录主题 X（如「AI 工具收藏」、「Go 微服务项目」、「读书笔记」等）。

向用户确认：
> 「我分析当前目录，主题应该是「X」，是否正确？」

如不对，询问用户提供正确主题名称。

### 第二步：引导配置

**已安装 `/brainstorming`：**
调用 `/brainstorming`，引导用户确认以下配置：
- 知识条目维度（默认：扩展版 C）
- hook 触发时机（默认：会话首次）

**未安装 `/brainstorming`：**
自行逐步引导，每次只问一个问题：

1. 「知识库语言：
   - A. 中文（推荐，适合中文用户和 Agent 协作）
   - B. 英文
   - C. 跟随条目原始语言（混合）
   [默认 A]」

2. 「知识条目维度：
   - A. 精简：What + Why + 源码地址
   - B. 标准：5W1H
   - C. 扩展：5W1H + 示例 + 与其他条目的关联
   [默认 C，直接回车确认]」

3. 「自动更新触发时机：
   - A. 每次会话的第一次对话（推荐，无感知）
   - B. 每次提示词提交时
   - C. 不配置自动更新
   [默认 A]」

3. 「这个目录有没有特殊的行为约定？参考以下常见类型，有则描述，没有直接回车跳过：
   - 收到某类输入时的自动处理（如收到 GitHub 链接时自动调研并询问是否 clone）
   - 特定文件类型的默认操作（如收到 PDF 时自动提取内容）
   - 与外部工具的交互规则（如自动同步到某个平台）
   - 进入目录时的默认行为（如自动显示索引）
   用户描述后，将其写入生成的 CLAUDE.md 的「行为约定」节。」

4. 「确认以上配置，开始初始化？」

### 第三步：执行脚手架

用户确认后，找到本 SKILL.md 所在目录，调用同目录下的 scaffold.sh：

```bash
bash "$(dirname <本SKILL.md的绝对路径>)/scaffold.sh" "<当前目录绝对路径>" "<主题名>"
```

脚手架会创建目录结构、从模板生成文件、设置权限。

### 第四步：生成知识条目

扫描目录下的一级子目录（排除 `.*`、`docs`、`skills` 开头的目录），对每个条目：

1. 读取其 `README.md`、`CLAUDE.md`、`package.json`、`pyproject.toml`、`Cargo.toml`、`go.mod` 等文件
2. 按用户选择的维度和语言生成 `.knowledge/projects/<name>.md`（所有描述性文字使用用户选择的语言，技术术语、命令、代码保持原样）
3. 在 `.knowledge/index.md` 追加一行（摘要使用用户选择的语言）

**中文目录名**的条目，文件名使用拼音或英文（如「远景」→ `yuanjing.md`）。

如果条目数量超过 10 个，使用并行 subagent 批量生成以提高效率。

### 第五步：输出摘要

```text
知识库初始化完成：<目录>
主题：<X>
条目数：<N>
可用命令：/kb、/kb <名称>、/kb refresh
自动更新：会话首次触发
```
## 知识条目格式

### index.md 格式

```markdown
# <主题> 索引

| 名称 | 摘要 | 类型 | 详情 |
|------|------|------|------|
| shannon | 企业级多 Agent AI 平台 | LLM框架 | [→](projects/shannon.md) |
```

类型标签参考：LLM框架、Agent工具、开发工具、AI应用、终端工具、知识管理、源码库、配置文件

### projects/\<name\>.md 格式

```markdown
# <名称>

> 一句话摘要

## What — 是什么
（2-4句，说明核心功能和定位）

## Why — 为什么用它
（相比同类的独特价值，或存在于此目录的原因）

## Who — 适合谁用
（目标用户群体）

## When — 什么场景下用
（典型使用场景，具体而非泛泛）

## Where — 源码 / 文档地址
（GitHub 地址或本地路径，从 README 或 git remote 获取）

## How — 怎么用（快速上手）
（安装/运行的核心命令，2-5行，可直接复制执行）

## 示例
（如有典型用法示例，无则省略此节）

## 与本目录其他条目的关联
（与同目录其他条目的关系，无则写「暂无」）
```

## 已有知识库的处理

如目录已存在 `.knowledge/`：
- 询问用户：「检测到已有知识库，是否：A. 追加新条目 B. 全量重建 C. 取消」
- 追加模式：只处理 index.md 中尚未收录的条目
- 全量重建：清空 `.knowledge/projects/`，重新生成所有条目

## 注意事项

- scaffold.sh 与本 SKILL.md 在同一目录下
- 生成知识条目时，质量优先于速度——宁可少写，不要写错
- 如某个条目目录下没有任何文档，根据目录名和文件列表推断，并在条目末尾注明「基于目录结构推断，可能不准确」
