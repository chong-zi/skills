# 领导汇报材料写作规范

把「我们做了什么」翻译成「领导能判断：做没做成、值多少、什么时候出」的材料。

## 核心判据

领导要的是三样东西：**已发生的事实 + 可验收的目标 + 经营价值**。

两个失败极端，都来自这一个判据：

- **太虚**：只有愿景和机制（"推动融合、打造一体化方案、形成差异化"），没有可验收的东西，领导读不到结果
- **太细**：只有落地动作和技术实现（"流程引擎、权限适配、深度集成、编排执行"），领导看不到目标

自检一句话：**这句话去掉后，领导还能判断"做没做成、值多少、什么时候出"吗？** 不能，就是虚或细。

---

## 何时使用

**使用：**
- 写季度/年度总结、下季度展望、经营分析材料
- 填汇报表格的"举措分解/完成情况/计划"列
- 材料被领导驳回，理由含"太虚""太细""读不懂""缺少目标性"
- 把技术团队的内部进展，改写成给管理层看的版本

**不使用：**
- 团队内部的技术周报、排期表（那是执行视角，不需要本规范）
- 立项书/技术方案（需要细节和技术论证，见其它 skill）

---

## 执行步骤

### 1. 先分季度，再分业务线
默认句式：**「<上季度>完成……。<本季度/下季度>展望：……」**
业务线用「；」并列，不做分块小标题、不编号（编号只用在表格单元格里）。

### 2. 摆事实：只写已发生的交付物
上季度部分全部用**已完成时态的交付物**：发版、上线、打通链路、覆盖率达成、方案发布、数据入库。
不写"推进、开展、持续"这类进行态动词。

### 3. 定目标：下季度部分给可验收的靶子
数字优先（覆盖率/采纳率/金额/降本比例/数量），没有数字就给交付物（发布X方案、上线X场景）。
不虚构基线——拿不到的数字宁可不写。

### 4. 每段一个价值收尾
段尾一句说明这对经营意味着什么：支撑拿单、支撑规模化复制、降低成本、形成壁垒。
价值句只在段尾出现一次，前面全部是事实。

### 5. 对照同表/同节的其它行
汇报材料是多人合写。写完先读同表其它 2~3 行，把自己的句式、长度、颗粒度对齐过去——**不一致比写得差更显眼**。

## 快速规则

### 结构
| 项 | 规则 |
|---|---|
| 主轴 | 季度：上季度成果 → 下季度展望，不用分块标题 |
| 单条句式 | 动作 + 交付物 +（括号放场景/数量）+ 价值短语 |
| 长度 | 单条 20~40 字；整段 150~250 字；表格单元格每行一条 |
| 编号 | 仅在表格单元格内用①②③；段落内用「；」并列 |

### 用词
- **禁用**实现层术语：架构名、框架名、协议名、引擎、编排、权限体系、底座、RAG、向量/图谱入库等
- **保留**领导认得出的产品名、系统名、版本号、客户名
- 场景要**具体枚举**（"A异常、B超限、C告警"），不要用大类概括（"异常发现+时机提醒"）
- 删冗余尾巴：场景说完即停，不加"并完成项目上线运行""并持续推进"这类

### 虚词替换表
| 虚（会驳回） | 实（通过） |
|---|---|
| 推动融合、打造一体化方案 | 完成X发版、打通Y链路 |
| 构建能力底座、赋能业务 | 落地A、B两个场景 |
| 实现智能化、提升效率 | 替代人工工时约 20%、单笔耗时由 2h 降至 30min |
| 形成差异化竞争能力 | 段尾保留一句，前面必须有事实垫底 |

### 指标
- 必须有可验收物：发版、链路打通、覆盖率、百分比目标、方案/BOM 发布
- 只写当季目标；上季度已达成的不重复作为新目标
- 拿不到数字就写交付物，不编数字、不编基线

## 常见驳回与修正

| 领导反馈 | 根因 | 修正动作 |
|---|---|---|
| "太虚了，没有干货" | 全是机制和愿景，无可验收物 | 换成上季度真实交付物 + 下季度量化目标 |
| "太具体，读不懂" | 堆技术实现动作 | 删术语，场景归并为业务语言，保留业务结果 |
| "缺少目标性" | 只有动作没有靶子 | 每条补一个可验收目标（数字或交付物） |
| "太长" | 同义反复、修饰语多 | 每条砍到 20~40 字，价值句只留段尾一句 |

---

## 自检清单

交付前逐条过：

- [ ] 每一条都有交付物或量化目标，没有纯愿景句
- [ ] 没有实现层术语（架构/协议/引擎/底座类）
- [ ] 上季度用完成时态，下季度用目标表述，时态没混
- [ ] 场景是具体枚举，不是大类概括
- [ ] 段尾有价值句，且全段只出现一次
- [ ] 长度在 150~250 字（表格每行 20~40 字）
- [ ] 与同表其它行的句式、颗粒度一致
- [ ] 没有虚构的基线数字
