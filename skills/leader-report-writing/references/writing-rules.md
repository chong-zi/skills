# 详细写作规则

## 一、句式模板

### 段落型（总结/展望正文）
```text
<上季度>完成<A 交付物>（版本/名称），<打通/上线/覆盖> <具体范围>；
<建成/发布> <B>，落地<场景1>、<场景2>等<C 类>场景。
<下季度>展望：<推进/迭代> <A> 试运行与<能力>积累，<指标>达<X%>；
<B>扩展<具体场景1>、<具体场景2>等<业务>场景，<发布/提供> <面向X的>方案。
```
### 表格单元格型（举措分解列）
```text
①<动词><交付物>（<场景/数量>），<价值短语>
②<动词><交付物>：<目标>，<价值短语>
③<动词><标准化物>，支撑<经营价值>
```
每行 20~40 字，三条以内。

## 二、动词表

**上季度（完成时态，只接交付物）**
完成 / 建成 / 发版 / 上线 / 打通 / 实现全覆盖 / 落地 / 发布

**下季度（目标态，接可验收靶子）**
推进 / 扩展 / 迭代 / 达成 / 发布 / 支撑

**禁用（进行态、无结果）**
持续推动 / 不断加强 / 深入开展 / 稳步推进 / 积极探索

## 三、颗粒度对照

| 层级 | 例子 | 用在哪 |
|---|---|---|
| 经营层 | 支撑新签、降低交付成本 XX%、覆盖 XX 客户 | 价值句，段尾一句 |
| 交付物层 | 发版、打通链路、场景落地、方案发布、BOM 发布 | 正文主体 ✅ |
| 动作层 | 调研、评审、打样、联调、配置 | 表格里可用，正文避免 |
| 技术层 | 框架、引擎、协议、编排、底座、接口 | 汇报材料禁用 |

判断方法：一条写完后，问"领导看完能拿它去追结果吗"。交付物层及以上可以，动作层和技术层不行。

## 四、数字怎么用

**优先给**：金额、覆盖率、采纳率、达成率、降本比例、耗时压缩比、数量（台/个/条）
**次优先给**：可验收的交付物（发版、发布方案、上线场景）
**不要给**：没有统计口径的估计值、为了让句子好看而编的基线

写法：
- ✅ "采纳率达 80%"（有目标值）
- ✅ "TOP100 高频场景全覆盖"（有范围）
- ❌ "由约 60% 提升至 80%"（基线无出处，别编）

## 五、长度控制

| 场景 | 字数 |
|---|---|
| 段落正文（一条业务线） | 150~250 字 |
| 表格单元格（每条） | 20~40 字 |
| 价值收尾句 | ≤25 字，全段只一次 |

超长时的砍法：先砍修饰语（"持续""不断""稳步"），再砍技术实现说明，最后砍同义重复的场景列举。

## 六、与同表对齐

汇报材料通常多人合写。动手前先读同表/同节其它 2~3 行，提取三个特征后套用：
1. 开头动词（发布/完成/统一/保障……）
2. 是否带数量或括号场景
3. 结尾是否有价值短语（"支撑……""匹配……""构建……"）

对齐句式比写出漂亮句子更重要——不一致会显得这段是外行补的。
