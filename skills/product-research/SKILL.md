# 产品调研技能

## 工作流程

```text
1. 解析输入 → 2. 信息采集 → 3. 多视角分析 → 4. 生成报告
```
### Step 1: 解析输入

识别用户提供的信息：

| 输入类型 | 处理方式 |
|----------|----------|
| 产品名称 | 使用 WebSearch 搜索官网、产品介绍、评测文章 |
| URL链接 | 使用 webReader 抓取内容，提取产品信息 |
| 指定深度 | 快速概览（基础分析）/ 深度分析（多轮搜索、多来源交叉验证） |

**默认行为**：若用户未指定深度，根据信息量自动判断。

### Step 2: 信息采集

按优先级采集信息：

1. **官网/产品页** - 产品定位、功能介绍、定价
2. **应用商店** - 用户评论、评分、下载量（如有）
3. **评测/分析文章** - 第三方视角、竞品对比
4. **公开数据** - 融资信息、团队背景（如有）

**工具使用**：
- 网页搜索：`WebSearch`
- 网页内容提取：`mcp__web_reader__webReader`

### Step 3: 多视角分析

依次从5个角色视角分析产品。详见 [references/roles.md](references/roles.md)。

| 视角 | 核心问题 |
|------|----------|
| 产品规划专家 | 产品定位是什么？功能架构如何？ |
| 产品洞察研究员 | 用户是谁？什么场景？解决什么痛点？ |
| 商业模式分析师 | 怎么赚钱？定价如何？商业化程度？ |
| 行业分析师 | 竞品有哪些？行业趋势如何？ |
| 投资人视角 | 值得投资吗？风险是什么？ |

### Step 4: 生成报告

输出 Markdown 格式报告，适配 Obsidian 笔记。

报告模板见 [references/template.md](references/template.md)。

**输出要求**：
- 结构清晰，使用表格整理对比信息
- 痛点-需求-功能-收益形成映射链
- 包含总结性判断，不只是罗列信息

## 输入示例

```text
# 示例1：仅产品名
帮我调研一下 Notion

# 示例2：提供链接
https://www.figma.com 帮我调研这个产品

# 示例3：指定深度
深度分析一下 Linear 这个产品

# 示例4：多个链接
https://xxx.com https://mp.weixin.qq.com/s/xxx 帮我调研这个产品
```

## 快速参考

**调研深度判断**：
- 快速概览：1-2轮搜索，覆盖核心模块
- 深度分析：3+轮搜索，多来源交叉验证，竞品对比更详细

**角色视角顺序**：规划 → 洞察 → 商业 → 行业 → 投资

**报告保存**：若用户使用 Obsidian，可建议保存到其笔记目录。
