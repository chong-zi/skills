# 服务器三层档案建模与维护规范

## 1. 三层模型

对每条信息先问一个问题：

| 判别问题 | 目标层 | 文件 | 更新规则 |
|---|---|---|---|
| 这是机器或服务的稳定事实吗？ | 静态层 | `profile.md`、`services.md` | 事实变化时更新，并在 `changelog/YYYY-MM.md` 记一条变更 |
| 这是某一次采集的时点快照吗？ | 动态层 | `current.md` | 每次采集整体覆盖，全文只对顶部采集时间负责 |
| 这是两个时点之间的变化或一次操作吗？ | 日志层 | `changelog/YYYY-MM.md` | 只追加，不改写已发生事实 |

## 2. 目录结构

```text
{别名}-{地址}/
├── README.md            唯一入口：定位、架构图、入口表、文档导航、维护规则
├── profile.md           静态机器档案：身份、系统、CPU、内存、存储布局、网络、安全、证书
├── services.md          静态服务清单：每个服务一个子对象（部署、端口、挂载、配置位置、健康检查）
├── current.md           动态现状：采集时的资源、容器运行态、镜像 ID、端口、systemd、健康检查
├── changelog/
│   └── YYYY-MM.md       月度变更日志：按服务器 / 服务子对象记录差异与操作
└── archive/             历史旧文档归档（可选，只读，不作为现状依据）
```

## 3. 服务子对象字段

每个服务在 `services.md` 中单独成节：

- **身份与部署**：服务名/容器名、运行方式（Docker Compose / Docker / systemd / 裸进程）、部署根目录、编排或配置文件路径、镜像仓库与标签、远程镜像源页面、重启策略、入口命令、Docker 网络、数据库或外部依赖。
- **端口与入口**：监听/映射地址（必须包含绑定地址，如 `127.0.0.1:3000` vs `0.0.0.0:3000`）、反向代理入口、路由配置文件位置。
- **持久化与配置**：挂载表（宿主机路径 → 容器路径、类型、读写模式、用途）、关键数据文件位置、备份注意项。
- **环境配置**：环境变量字段名清单；密码、密钥、Token 只写“已配置，值见服务器配置文件”。
- **健康检查**：本机检查命令、代理链路检查命令、预期状态码或输出。

## 4. 关键纪律

- **记位置不抄全文**：Compose、Nginx、应用配置全文以服务器原件为准；档案只记路径、关键路由关系和非敏感参数。
- **通用方法抽离**：Docker 升级、SQLite 备份、Nginx reload/排错等通用流程放在独立操作指南，不在每台服务器档案里重复维护。
- **漂移标签必须拆层**：`latest`、`main` 等可漂移标签写在 `services.md` 时必须注明“非固定版本号”；实际镜像 ID、RepoDigest、应用自身报告的版本号写入 `current.md`。
- **容器内部 IP 归动态层**：Docker bridge 分配的容器 IP 会随重建变化，写入 `current.md`。
- **未核实不冒充现状**：云安全组、云备份策略、外部域名解析等主机内采集不到的信息，未检查时明确写“未核实”。
- **采集发现不虚构时间**：对比上次快照发现某容器或文件已不存在，但不知道确切操作时间时，在当月日志标记为“采集发现（相对 YYYY-MM-DD 快照）”。
- **无变化也要留痕**：定期采集若核心静态项与服务运行态无实质差异，也在当月日志追加一条“已采集，未发现架构或服务配置变化”，把“检查过且没变”与“未检查”区分开。
